# Dotfiles

Repositorio bare de dotfiles. Gestionado con Git usando `$HOME` como árbol de trabajo (sin carpeta de checkout intermedia).

## Instalación en una máquina nueva

### 1. Clonar el repositorio como bare

```bash
git clone --bare git@github.com:sudo-devanescent/dotfiles.git "$HOME/.dotfiles"
```

### 2. Crear el alias `dotfiles`

Añade esta línea a tu `~/.bashrc` (o `~/.zshrc` si usas Zsh):

```bash
alias dotfiles='git --git-dir="$HOME/.dotfiles/" --work-tree="$HOME"'
```

Recarga la shell:

```bash
source ~/.bashrc   # o source ~/.zshrc
```

### 3. Ocultar archivos no rastreados en `dotfiles status`

Sin esto, `dotfiles status` listaría absolutamente todo tu `$HOME` como "untracked":

```bash
dotfiles config --local status.showUntrackedFiles no
```

### 4. Hacer el checkout

```bash
dotfiles checkout
```

**Si falla** con un error tipo:

```
error: The following untracked working tree files would be overwritten by checkout:
    .bashrc
Please move or remove them before you continue.
```

Significa que ya existen archivos en `$HOME` con el mismo nombre (comunes en instalaciones nuevas de Linux). Respáldalos y reintenta:

```bash
mkdir -p "$HOME/.dotfiles-backup"
mv "$HOME/.bashrc" "$HOME/.dotfiles-backup/"   # repetir para cada archivo listado en el error
dotfiles checkout
```

### 5. Verificar

```bash
dotfiles status
```

Debe mostrar `nothing to commit, working tree clean`.

## Notas técnicas

- Los archivos versionados están normalizados a saltos de línea **LF** (Unix), independientemente del sistema operativo desde el que se edite o clone. Esto se controla vía `info/attributes` dentro del propio repositorio (`$GIT_DIR/info/attributes`, no un `.gitattributes` visible en `$HOME`), por lo que viaja automáticamente con cada clon.
- No uses `dotfiles add .` ni `dotfiles add -A` nunca — el árbol de trabajo es `$HOME` completo. Añade siempre rutas explícitas.
